# Implementation prompt — Popular courses on home, full catalog at /courses

## Goal

The home page shows only the three popular courses; "View all courses" leads to
a new `/courses` page listing the whole catalog.

## Skills and docs read

- `CLAUDE.md` sections 3, 5, 7, 13 — reproduce the design, pages read-only,
  server-side reads, derived numbers, run the checks.
- `sanity-best-practices` conventions already established in
  `web/sanity/lib/queries.ts` (`defineQuery`, unique names, shared fragments).
- `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/page.md`
  conventions already applied in `app/courses/[slug]/page.tsx`.

## Code inspected

- `web/sanity/lib/queries.ts` — `courseCardFragment` and `COURSES_CATALOG_QUERY`
  exist; a popular-only query does not.
- `web/app/page.tsx` — reads the full catalog and renders every course; the
  "View all courses" link is still `href="#"`.
- `web/app/components/ui/Cards.tsx` — `CourseCard` already takes `href` and
  `cover`.
- `web/app/courses/[slug]/page.tsx` — its breadcrumb "All Courses" currently
  points at `/` because no catalog index existed.
- `studio/sanity.cli.ts` + `studio/package.json` — TypeGen is wired
  (`npm run typegen` in `studio`, reads `../web/**/*.{ts,tsx}`, writes
  `../web/sanity.types.ts`), so a new query gets a generated type.
- Live data: exactly three courses have `popular: true` — Building LLM
  Applications, Next.js for Production, TypeScript Deep Dive.

## Decisions and assumptions

1. **New query** `POPULAR_COURSES_QUERY` in `queries.ts`, reusing
   `courseCardFragment`: courses with `popular == true` and a slug, ordered
   `studentCount desc, title asc`, sliced `[0...3]`. Filtering on the flag is
   honest about what "popular" means; the slice enforces the three-card row even
   if an author flags a fourth.
2. **Fewer than three popular courses** is not padded from the rest of the
   catalog — the grid simply shows what is flagged, and the existing empty state
   covers zero. Padding would make the flag meaningless.
3. **TypeGen** is run from `studio` after adding the query so
   `POPULAR_COURSES_QUERY_RESULT` exists rather than being hand-written.
4. **New route** `app/courses/page.tsx`, a server component reading
   `COURSES_CATALOG_QUERY`. It reuses the home section's chrome and the exact
   same card grid — there is no design image for this page, so it borrows the
   approved home patterns rather than inventing a new look: `TopNav`, the
   `max-w-[904px]` container, the display-serif page heading, and the
   3-column card grid.
5. The catalog page shows a derived count under the heading (for example
   "10 courses") so the page says something true rather than repeating the
   title. No filters, sorting, or pagination — out of scope.
6. **Card rendering is shared.** The mapping from a Sanity course to
   `CourseCard` props (cover URL, level, duration, module count, href) moves
   into one `CourseGrid` component used by both pages, so the two lists cannot
   drift apart.
7. **Home** swaps to `POPULAR_COURSES_QUERY` and its "View all courses" anchor
   becomes a `Link` to `/courses`. The section heading stays "All Courses" as in
   the approved design — changing the wording is a design decision, not mine.
8. **Breadcrumb** on the course detail page now points "All Courses" at
   `/courses` instead of `/`.
9. Cache tags: home uses `courses`, the catalog page uses `courses`, so one
   revalidation covers both.

## Files expected to change

New:

- `web/app/courses/page.tsx` — the catalog index.
- `web/app/components/home/CourseGrid.tsx` — the shared Sanity-course → card
  grid.

Modified:

- `web/sanity/lib/queries.ts` — add `POPULAR_COURSES_QUERY`.
- `web/sanity.types.ts` — regenerated by TypeGen, not edited by hand.
- `web/app/page.tsx` — popular query, shared grid, real "View all courses" link.
- `web/app/courses/[slug]/page.tsx` — breadcrumb target.

## Requirements

- Home renders at most three cards, all of them flagged popular.
- `/courses` renders every published course, popular first then by title, each
  linking to its detail page.
- Both grids come from the same component; no duplicated formatting logic.
- Every number is derived from the query result.
- Both pages stay server components; no `"use client"`.
- Responsive to 375px with no horizontal scroll.

## Security considerations

- Both reads go through `sanityFetch` on the server; the browser receives HTML
  and public image URLs only, never the read token.
- Neither query takes user input.

## Acceptance criteria

1. The home "All Courses" section shows exactly the three popular courses.
2. "View all courses" navigates to `/courses`, which lists all ten with a
   correct count.
3. Cards on both pages link to the right detail page.
4. The course page breadcrumb returns to `/courses`.
5. `npm run typecheck`, `npm run lint`, `npm run build` pass in `web`, and
   `npm run typegen` in `studio` regenerates types cleanly.

## Checks to run

- `studio`: `npm run typegen`.
- `web`: `npm run typecheck`, `npm run lint`, `npm run build`, plus a dev pass
  with screenshots of `/` and `/courses`.

   Production, TypeScript Deep Dive.
3. Click "View all courses" → `/courses` shows all ten with the count.
4. Click a card there → its detail page; use the breadcrumb to return to
   `/courses`.
5. Narrow to 375px on both pages and confirm no horizontal scroll.
